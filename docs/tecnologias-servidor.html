Sistema de turnos · CAPS

Tecnologías del servidor

Con qué está hecho el backend del sistema y para qué se usa cada herramienta.

En una línea: servidor desarrollado en Node.js con Express, que expone una API REST, guarda los datos en MariaDB, autentica con JWT y guarda las contraseñas cifradas con bcrypt.

Lenguaje y entorno

El servidor está escrito en JavaScript y corre sobre Node.js, el entorno que permite ejecutar JavaScript fuera del navegador. Usa el sistema de módulos CommonJS (require / module.exports).

Herramientas principales

HerramientaVersiónPara qué se usa
Node.js—Entorno de ejecución del servidor.
Express5.3Framework web: recibe los pedidos HTTP en las rutas /api/... y decide qué responder. Cada archivo de routes/ agrupa las rutas de un rol (secretaría, médico, paciente).
MariaDB10.4Base de datos relacional (incluida en XAMPP). Guarda médicos, pacientes, horarios, turnos, atenciones, recetas y fichas clínicas.
mysql23.24Librería para conectarse a la base, con consultas parametrizadas y transacciones.
jsonwebtoken (JWT)9.0Inicio de sesión: al entrar con DNI y contraseña, el servidor entrega un "pase" firmado que el navegador envía en cada pedido.
bcryptjs3.0Cifra las contraseñas con el algoritmo bcrypt. Nunca se guardan en texto.
node-cron4.6Tarea programada que cada 5 minutos busca turnos próximos y envía el recordatorio.
nodemailer10.5Envío de correos (recordatorios de turno y recuperación de contraseña) a través de Gmail.
dotenv18.0Lee la configuración del archivo .env (datos de la base, clave secreta, puerto, correo).
cors2.8Permite que la interfaz web se comunique con la API desde otra dirección durante el desarrollo.
nodemon3.1Solo para desarrollo: reinicia el servidor automáticamente al guardar cambios.

Forma de programación

El código no está organizado con clases (programación orientada a objetos), sino en módulos con funciones, en una arquitectura en capas:

  • Rutas (routes/): una por rol; reciben el pedido y devuelven la respuesta.
  • Middleware (middleware/auth.js): verifica la sesión y el rol antes de cada ruta.
  • Módulos de dominio: la lógica del negocio, separada de las rutas. Por ejemplo, calculo-turnos.js calcula los horarios libres con funciones puras (sin base de datos), lo que permite probarlas de forma automática; reservas.js es el único camino para reservar un turno.
  • Base de datos (db/schema.sql): tablas, claves y restricciones.

Seguridad

  • Contraseñas cifradas con bcrypt; sesiones con JWT que se invalidan al cambiar la contraseña.
  • Límite de intentos de inicio de sesión (5 fallos bloquean 15 minutos).
  • Cada ruta controla el rol del usuario; a los datos ajenos se responde "no encontrado".
  • Reservas dentro de una transacción con bloqueo, más una clave única en la base que impide dar dos veces el mismo horario.
  • La cuenta que usa el sistema en la base no tiene permiso para borrar: los datos se desactivan, no se eliminan.
